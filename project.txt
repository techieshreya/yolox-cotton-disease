PROJECT OVERVIEW
================================================================================

This project implements an improved YOLOX (You Only Look Once X) object
detection model specifically designed for detecting and classifying cotton
plant diseases with severity levels. The system can identify multiple
co-occurring diseases on cotton plants with high accuracy.

Key Features:
- Multi-disease detection on cotton plants
- Severity level classification
- Improved architecture with CBAM attention and enhanced SPP
- Auto-optimization for different GPU configurations
- Real-time VRAM monitoring and optimization
- Comprehensive training pipeline with visualization

Disease Classes:
1. Healthy (class 0)
2. Diseased (class 1)
Note: The config mentions 5 classes (curl_stage1, curl_stage2, healthy,
leaf_enation, sooty), but the dataset class mapping shows 2 classes.

Research Paper:
Based on: "Handling Severity Levels of Multiple Co-Occurring Cotton Plant
Diseases Using Improved YOLOX Model"

MODEL ARCHITECTURE
================================================================================

YOLOX Structure:
The model consists of three main components:

1. BACKBONE (CSPDarknet):
   - Focus layer: Reduces spatial dimensions, increases channels
   - Dark2: 2x downsampling + CSP bottleneck
   - Dark3: 2x downsampling + CSP bottleneck (3x depth)
   - Dark4: 2x downsampling + CSP bottleneck (3x depth)
   - Dark5: 2x downsampling + SimSPPF + CSP bottleneck

   Output feature maps: dark3, dark4, dark5 (multi-scale features)

2. NECK (YOLOPAFPN - Path Aggregation FPN):
   - Top-down pathway with lateral connections
   - Bottom-up pathway with concatenation
   - Produces three feature pyramid levels for detection
   - Enables multi-scale object detection

3. HEAD (YOLOXHead):
   - Decoupled head design (separate cls and reg branches)
   - Per-level prediction heads for different scales
   - Outputs: [reg (4), obj (1), cls (num_classes)]
   - Anchor-free detection (no predefined anchors)

Model Variants:
- YOLOX-S (Small):   depth_mul=0.33, width_mul=0.50, ~9M parameters
- YOLOX-M (Medium):  depth_mul=0.67, width_mul=0.75, ~25M parameters
- YOLOX-L (Large):   depth_mul=1.00, width_mul=1.00, ~54M parameters
- YOLOX-X (XLarge):  depth_mul=1.33, width_mul=1.25, ~99M parameters

Improvements Over Standard YOLOX:
1. CBAM Attention: Channel and Spatial attention in CSPLayer
2. Enhanced SPP: Multi-scale pooling (3x3, 5x5, 7x7, 9x9)
3. SimSPPF: Simplified SPPF for efficient feature extraction

Stride Levels:
- Level 1: Stride 8  (high resolution, small objects)
- Level 2: Stride 16 (medium resolution, medium objects)
- Level 3: Stride 32 (low resolution, large objects)


LOSS FUNCTION
================================================================================

YOLOX uses a composite loss with SimOTA (Simplified Optimal Transport
Assignment) for dynamic label assignment.

Loss Components:

1. Classification Loss:
   - Binary Cross Entropy with Logits
   - Applied only to positive samples
   - One-hot encoded class targets

2. Regression Loss (GIoU):
   - Generalized Intersection over Union
   - Better than standard IoU for localization
   - Accounts for non-overlapping boxes
   - Formula: GIoU = IoU - (C - Union) / C
     where C is the area of the smallest enclosing box

3. Objectness Loss:
   - Binary Cross Entropy with Logits
   - Applied to all predictions
   - Positive samples: 1.0
   - Negative samples: 0.0

Total Loss:
   L = (5.0 * L_reg + L_cls + L_obj) / num_foreground

SimOTA (Label Assignment):
- Dynamic assignment based on cost matrix
- Cost = 3.0 * reg_cost + 1.0 * cls_cost
- Filters candidates by:
  1. Box center must be inside GT box
  2. Prediction center within radius (2.5 * stride)
- Dynamic K: Top-k candidates based on IoU
- Prevents multiple predictions for same ground truth


DATASET PIPELINE
================================================================================

Data Format:
- Images: JPG/PNG format
- Annotations: Pascal VOC XML format
  Structure:
    <annotation>
      <filename>image.jpg</filename>
      <size>
        <width>...</width>
        <height>...</height>
      </size>
      <object>
        <name>class_name</name>
        <bndbox>
          <xmin>...</xmin>
          <ymin>...</ymin>
          <xmax>...</xmax>
          <ymax>...</ymax>
        </bndbox>
      </object>
    </annotation>

Dataset Class (CottonDiseaseDataset):
- Reads images and paired XML annotations
- Validates bounding box coordinates (clips to image bounds)
- Applies augmentations using Albumentations
- Returns: (image_tensor, targets_tensor)
  - image_tensor: [3, H, W], normalized
  - targets_tensor: [N, 5] = [x1, y1, x2, y2, class_id]

Training Augmentations:
1. Resize to fixed input size (640x640 default)
2. HorizontalFlip (p=0.5)
3. ShiftScaleRotate (shift=0.1, scale=0.1, rotate=15°, p=0.5)
4. RandomBrightnessContrast (p=0.3)
5. ColorJitter (brightness, contrast, saturation, hue, p=0.5)
6. Blur (p=0.1)
7. GaussNoise (p=0.1)
8. Normalize (ImageNet mean/std)
9. ToTensorV2

Validation Augmentations:
1. Resize to fixed input size
2. Normalize (ImageNet mean/std)
3. ToTensorV2

Bounding Box Handling:
- Format: Pascal VOC (x_min, y_min, x_max, y_max)
- Clipping: Coordinates clipped to image bounds
- Min visibility: 0.1 (boxes kept if >10% visible after augmentation)


TRAINING PIPELINE
================================================================================

Three Training Modes:

1. train.py (Manual Configuration):
   - User specifies all parameters
   - Command line arguments for full control
   - Requires understanding of optimal settings
   - Good for experienced users

2. train-max.py (Auto-Optimized):
   - Automatically detects GPU specifications
   - Optimizes batch size, model size, input resolution
   - Uses VRAM monitoring for optimal settings
   - Prevents out-of-memory errors
   - Recommended for all users

3. start_training.py (Interactive Launcher):
   - Interactive CLI for selecting training mode
   - Hardware detection and recommendations
   - Guided parameter selection
   - Shows expected training time
   - User-friendly for beginners

Training Process:

Initialization:
1. Load datasets (train and validation)
2. Create DataLoaders with collate_fn
3. Initialize model (YOLOX with specified phi)
4. Setup optimizer (AdamW, lr=1e-3, weight_decay=5e-4)
5. Setup scheduler (Cosine Annealing with warmup)
6. Initialize loss function (YOLOXLoss with SimOTA)

Learning Rate Schedule:
- Warmup: 5 epochs, linear warmup to base LR
- Main: Cosine Annealing, eta_min = base_lr * 0.01
- Formula: lr = eta_min + (base_lr - eta_min) * 0.5 * (1 + cos(π * t / T))

Training Loop (per epoch):
1. Set model to train mode
2. Apply LR warmup if epoch < warmup_epochs
3. For each batch:
   a. Forward pass through model
   b. Calculate loss (SimOTA + GIoU + BCE)
   c. Backward pass (compute gradients)
   d. Gradient clipping (max_norm=1.0)
   e. Optimizer step
4. Validation phase:
   a. Set model to eval mode
   b. Forward pass (no gradients)
   c. Post-process predictions (NMS)
   d. Calculate mAP per class
   e. Measure inference time
5. Save best model if mAP improves
6. Save checkpoint every N epochs
7. Visualize predictions every 5 epochs
8. Update learning rate (scheduler step)

Post-Processing (NMS):
1. Decode predictions from all FPN levels
2. Convert box format (cxcywh → xyxy)
3. Apply confidence threshold (default: 0.01)
4. Combine objectness and class confidence
5. Apply Non-Maximum Suppression (IoU threshold: 0.5)
6. Return final detections per image

Evaluation Metrics:
- mAP@0.5 (mean Average Precision at IoU=0.5)
- AP per class (Average Precision for each disease)
- Inference time (seconds per validation set)
- Training loss, Validation loss
- Learning rate (logged each epoch)

Checkpointing:
- best_model.pth: Best model by mAP
- epoch_N.pth: Periodic checkpoints with full state
  Includes: model_state_dict, optimizer_state_dict, epoch, mAP


AUTO-OPTIMIZATION (train-max.py)
================================================================================

GPU Memory Detection:
- Detects total and available VRAM
- Monitors VRAM usage in real-time
- Prevents out-of-memory errors

Optimization Strategy:

VRAM-Based Configuration:
┌─────────────┬─────────┬──────────────┬────────────┬─────────┐
│ VRAM (GB)   │ Model   │ Input Size   │ Batch Size │ AMP     │
├─────────────┼─────────┼──────────────┼────────────┼─────────┤
│ 24+         │ YOLOX-X │ 640x640      │ 16         │ Yes     │
│ 16-24       │ YOLOX-L │ 640x640      │ 12         │ Yes     │
│ 12-16       │ YOLOX-L │ 640x640      │ 8          │ Yes     │
│ 10-12       │ YOLOX-M │ 640x640      │ 8          │ Yes     │
│ 8-10        │ YOLOX-M │ 640x640      │ 6          │ Yes     │
│ 6-8         │ YOLOX-S │ 640x640      │ 4          │ Yes     │
│ 4-6         │ YOLOX-S │ 512x512      │ 2          │ Yes     │
│ <4          │ YOLOX-S │ 416x416      │ 1          │ Yes     │
└─────────────┴─────────┴──────────────┴────────────┴─────────┘

Memory Estimation:
- Model parameters memory
- Activation memory (3.5x input size)
- Gradient memory (equal to parameters)
- Optimizer state memory (2x parameters for AdamW)
- Total estimated before training starts

Features:
1. Automatic batch size optimization
2. Mixed precision training (AMP) for faster training
3. Gradient scaler for stable mixed precision
4. Real-time VRAM monitoring
5. Graceful degradation if memory insufficient
6. Detailed memory breakdown reporting

Expected Training Times (150 epochs):
- YOLOX-X (24GB): ~6-8 hours
- YOLOX-L (16GB): ~8-10 hours
- YOLOX-M (8GB):  ~10-12 hours
- YOLOX-S (6GB):  ~12-14 hours

USAGE INSTRUCTIONS
================================================================================

1. Setup Environment:
   ```bash
   # Install dependencies
   pip install -r requirements.txt

   # Or use uv (faster)
   uv sync
   ```

2. Check CUDA Availability:
   ```bash
   python main.py
   ```
   Output should show GPU detected and CUDA version.

3. Prepare Dataset:
   - Place images in data/train/, data/valid/, data/test/
   - Ensure each image has a corresponding .xml annotation
   - XML files should be in Pascal VOC format
   - Verify class names match dataset.py class_map

4. Interactive Training (Recommended):
   ```bash
   python start_training.py
   ```
   - Detects hardware automatically
   - Guides you through parameter selection
   - Recommends optimal settings
   - Shows expected training time

5. Auto-Optimized Training:
   ```bash
   python train-max.py --epochs 150 --num_classes 5
   ```
   - Automatically optimizes for your GPU
   - No parameter tuning needed
   - Uses maximum available VRAM safely

6. Manual Training:
   ```bash
   python train.py \
       --phi m \
       --batch_size 4 \
       --epochs 200 \
       --input_size 640 640 \
       --num_classes 5 \
       --save_dir ./checkpoints
   ```

7. Monitor Training:
   - Watch console output for loss and mAP
   - Check checkpoints/ for saved models
   - View predictions_epoch_N.png for visualizations
   - Use nvidia-smi to monitor GPU usage

8. Resume Training (if interrupted):
   - Load checkpoint in train.py
   - Restore model_state_dict and optimizer_state_dict
   - Continue from saved epoch

PERFORMANCE OPTIMIZATION
================================================================================

GPU Optimizations:
1. Mixed Precision Training (AMP):
   - Reduces memory usage by ~40%
   - Speeds up training by ~2-3x
   - Automatically enabled in train-max.py

2. Gradient Accumulation:
   - Simulate larger batch sizes
   - Useful for limited VRAM
   - Not currently implemented (can be added)

3. Gradient Clipping:
   - Max norm: 1.0
   - Prevents exploding gradients
   - Stabilizes training

4. DataLoader Optimization:
   - num_workers: Parallel data loading
   - pin_memory: Faster CPU→GPU transfer
   - Optimized collate_fn

5. cuDNN Benchmark:
   - Enabled by default
   - Finds fastest convolution algorithm
   - ~10-20% speedup for fixed input sizes

Memory Optimizations:
1. Batch size tuning based on VRAM
2. Empty cache between validation runs
3. Efficient tensor operations
4. Avoid unnecessary copies

Data Pipeline:
1. Efficient image loading (OpenCV)
2. Fast augmentations (Albumentations)
3. On-the-fly preprocessing
4. Caching disabled (to save VRAM)


TROUBLESHOOTING
================================================================================

Common Issues:

1. CUDA Out of Memory (OOM):
   Solutions:
   - Reduce batch size
   - Use smaller model (s instead of m)
   - Reduce input size (512x512 or 416x416)
   - Use train-max.py for auto-optimization
   - Enable mixed precision training

2. Loss is NaN:
   Causes:
   - Learning rate too high
   - Gradient explosion
   - Invalid bounding boxes
   Solutions:
   - Reduce learning rate
   - Check dataset annotations
   - Enable gradient clipping (already enabled)

3. mAP Not Improving:
   Causes:
   - Insufficient training data
   - Poor augmentations
   - Learning rate issues
   Solutions:
   - Train longer (200+ epochs)
   - Adjust augmentation parameters
   - Use learning rate warmup (already included)
   - Check class balance in dataset

4. Slow Training:
   Solutions:
   - Increase num_workers (but not too high)
   - Use SSD instead of HDD for dataset
   - Enable AMP (mixed precision)
   - Reduce validation frequency

5. Annotation Errors:
   Symptoms:
   - "Bounding box out of bounds" warnings
   - Crashes during data loading
   Solutions:
   - Check XML files for invalid coordinates
   - Dataset class already clips boxes to image bounds
   - Verify class names match class_map

6. No GPU Detected:
   Solutions:
   - Check CUDA installation: nvidia-smi
   - Verify PyTorch CUDA version matches system CUDA
   - Reinstall PyTorch with correct CUDA version
   - Check GPU drivers


ADVANCED FEATURES
================================================================================

CBAM Attention Mechanism:
- Channel Attention: Learns importance of each channel
- Spatial Attention: Learns importance of spatial locations
- Applied in CSPLayer after feature extraction
- Improves feature representation
- ~2-3% mAP improvement

SimOTA Label Assignment:
- Dynamic assignment (vs fixed anchors)
- Optimal Transport-based matching
- Prevents duplicate predictions
- Improves recall for small objects
- More stable training than OTA

Enhanced SPP:
- Multi-scale pooling: 3x3, 5x5, 7x7, 9x9
- Captures features at different receptive fields
- Better for varying object sizes
- Concatenation of all scales

Decoupled Head:
- Separate branches for classification and regression
- Reduces task conflict
- Faster convergence
- Better accuracy than shared head
